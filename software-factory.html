superhuman/Software factory

A software factory for other people's repositories.

A software factory is a repeatable system in which agents do defined work and pass it through checks and review before it ships. superhuman is one, built for a specific job: taking open issues in projects you don't own to pull requests their maintainers merge, from your fork, under your name.

The stations

Every contribution moves through the same stations. Each one is a specialist agent with a contract, and each hands a file to the next.

Throughput

One contribution is /contribute. /contribute-loop 5 runs five in a row; /contribution-fleet 3 runs three in parallel across different repositories, each with its own state directory, clone and lock, so runs cannot step on each other. /preferences decides what the intake station looks for.

Controls

  • Bounded compute. Every run ends, by quality or by budget: the iteration cap is set from the size of the diff.
  • Bounded blast radius. Pushes go only to your fork, with --force-with-lease; only allowlisted commands run.
  • A human at the last gate. Maintainers decide whether to merge, and reviews that arrive after a run ends are yours to answer.
  • Visible origin. By default, each pull request says it was opened with superhuman.

What it has shipped

Since April 2026, maintainers of open-source projects with 1,000+ stars have merged 121 pull requests opened with superhuman, across 48 projects, including Hugging Face transformers, Deno, ClickHouse and Google's gemini-cli. 35 of them are in superpowers and everything-claude-code, two plugins superhuman builds on. Every one is listed with its link on the Merge Wall.

How it differs from a team software factory

Most software factories run inside a company: the team owns the repository, the backlog and the merge button. superhuman works on repositories you don't own. Its input is a public issue, its output is a pull request from your fork, and the final quality gate belongs to strangers: the project's maintainers. That is why so much of the factory is about reading the project before writing anything, and about stopping rather than sending weak work.

Questions

What is an AI software factory?

A repeatable development system in which AI agents do defined pieces of work, such as planning, building and reviewing, and pass the results through checks before anything ships.

Is superhuman open source?

Yes, MIT licensed. The agent contracts, the scripts they call, the schemas and the tests are all in the repository.

Can it run unattended?

Yes, within limits. Runs are bounded by an iteration cap, a lock per repository and an allowlist of commands. The pull request opens as a draft, and maintainers decide whether to merge.

Does it work on my company's private repositories?

It is built for contributing to public open-source projects from a fork. Its issue selection, conventions learning and outcome tracking assume a public project with its own maintainers.
